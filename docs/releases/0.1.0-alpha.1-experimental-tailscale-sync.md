# Experimental Tailscale save-sync preview

This preview synchronizes only manually added games whose save folder the user
selects explicitly. Steam games are rejected and continue to use Steam Cloud.

## Pairing two devices

1. Install the same NovaLauncher build and Tailscale on both Windows devices.
2. Confirm both devices are online in the same tailnet.
3. In NovaLauncher Settings, enter the other device's Tailscale IP on each device.
4. On one device choose **Generate 24-hour invitation**. Use **Copy code** or
   read the six digits, transfer them through a trusted channel during the next
   24 hours, then use **Paste code** or type them and choose **Accept
   invitation** on the other device. Clipboard clearing after 60 seconds is
   best-effort and cannot erase copies retained by clipboard-history tools.
5. Windows may request firewall approval for NovaLauncher on the Tailscale
   network. Do not expose TCP 47471 through a public router.
6. For each manual game, open its details and choose its exact save folder.

The Settings card displays **PAIRED** plus the pinned device ID after successful
redemption. The accepting device updates immediately. On the device that
generated the invitation, choose **Refresh pairing status** after the other
device accepts it. If **Accept invitation** is disabled, first save the
inviter's Tailscale IP and enter or paste all six digits. Redemption errors are
shown directly in the pairing card.

For a game added independently on both devices, open its details on each device,
use the same sync label and platform, and choose **Link automatically with paired
device**. The devices independently derive the same private identity from their
existing pairing credential, so no clipboard or simultaneous physical access is
required. Verify the game and save-folder choices yourself: linking authorizes
those two entries to exchange saves. Raw link copy/paste remains available only
for advanced recovery. Downloads & Saves shows current activity, retained
snapshot state, peer acknowledgment, and a queued-upload retry control.

When a mapped folder already contains saves, NovaLauncher asks whether to upload
them immediately. Confirm the game and folder before choosing **Upload existing
saves**, or choose **Not now** and use **Sync now** later. This removes the need
to launch and exit a game solely to create its first snapshot.

Before launch, NovaLauncher checks for a newer peer generation. After the game
process exits, it waits for two stable scans and sends only changed files. If
both devices changed the same baseline, launch is blocked until Keep local, Use
remote, or Keep both is selected. Every remote restore creates a managed backup.

The six-digit code is only short-lived bootstrap authorization and is never a
save-encryption key. NovaLauncher stores only its salted PBKDF2-SHA256 verifier,
locks it after three persisted failures, and accepts it only through the
Tailscale-bound listener. A separate random 256-bit session secret is stored in
Windows Credential Manager and excluded from JSON, logs, exports, and release
artifacts. An invitation is single-use: the first authenticated device consumes
it and its stable identity is pinned.
Expired, replayed, differently identified, and already-consumed invitations are
rejected. After pairing, the devices reconnect automatically until one is
explicitly revoked. Generating a new invitation before initial pairing
invalidates the prior pending invitation.

This feature is not release-qualified until the checklist's real two-device,
interruption, firewall, disk-full, scale, and accessibility tests pass.
