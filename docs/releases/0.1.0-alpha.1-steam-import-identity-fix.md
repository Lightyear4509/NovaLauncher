# Steam import identity fix

## Root cause

The JSON source serializer wrote strongly typed game IDs as nested values but
reconstructed them as empty GUIDs during staged read-back. One manual record
could exist, but a Steam import introduced multiple records that all appeared to
have the same empty identity. The atomic store correctly rejected that staged
document instead of publishing corrupt data.

## Resolution

- Added bounded JSON converters that write game and collection IDs as GUID
  strings and accept the legacy object representation.
- A legacy empty manual-game ID is recovered to one deterministic non-empty ID
  and rewritten safely on the next successful mutation.
- Empty IDs are explicitly rejected by document policy.
- Steam registry roots are canonicalized before deduplication.
- An unavailable configured library is a per-library warning; valid libraries
  remain importable.
- Added an isolated diagnostic mode and regression tests for distinct-ID staged
  save/read-back behavior.

Using a copy of the actual local `games.json` and read-only access to the actual
Steam manifests, the diagnostic preview found seven additions and two skips:
the unavailable `O:\SteamLibrary` root and one manifest whose installed bonus
directory is absent. Atomic commit succeeded with eight games and eight distinct
IDs. Neither the real NovaLauncher data nor Steam files were modified.

Formatting, Release build, and all 159 tests passed with zero failures/skips.
